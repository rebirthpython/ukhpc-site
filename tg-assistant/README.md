# Личный ИИ-ассистент в Telegram на Claude

Telegram-бот с HTML5 мини-приложением. Внутри работает Claude (по умолчанию `claude-opus-5-5`)
через официальный Claude API. Пользоваться могут только люди из белого списка, все расходы идут
с **твоего** API-аккаунта, а дневной и месячный лимиты в долларах ты задаёшь сам.

## Что умеет

- **Чат прямо в Telegram.** Ответ печатается по мере генерации, Markdown превращается в
  форматирование Telegram, длинные ответы делятся на несколько сообщений.
- **Мини-приложение (HTML5).** Открывается кнопкой слева от поля ввода. В нём пузырьки
  сообщений, подсказки для старта, отправка фото, копирование ответов и блоков кода. Цвета
  берутся из темы Telegram, светлой или тёмной.
- **Общая история.** Можно начать разговор в чате и продолжить в приложении, и наоборот.
- **Фото.** Можно прислать снимок одежды, еды, документа или скриншота и задать вопрос.
- **Веб-поиск** для погоды, новостей, цен и расписаний. Его можно отключить.
- **Лимиты расходов:** на день, на месяц и отдельно на человека. Команда `/usage` показывает,
  сколько уже потрачено.
- **Приватность.** Бот отвечает только тем, чьи ID есть в `ALLOWED_USER_IDS`. Остальные видят
  свой ID, а ты получаешь уведомление. Мини-приложение проверяет подпись Telegram (`initData`).

## Про лимиты (важно)

Подписку claude.ai (Pro/Max) **нельзя** подключить к боту. Она личная, и по условиям Anthropic её
нельзя передавать другим людям или встраивать в свои приложения. Для ботов есть **Claude API**:
ключ создаётся в [console.anthropic.com](https://console.anthropic.com) на твоём аккаунте,
а оплата идёт с баланса этого аккаунта. Получается, девушка пользуется твоими деньгами и
твоими лимитами, только уже легально.

Чтобы расходы не вышли из-под контроля:
1. Пополни баланс в Console (Billing). Бот не потратит больше, чем лежит на балансе.
2. В Console (Settings → Limits) поставь месячный лимит расходов. Это жёсткая граница на стороне
   Anthropic.
3. В `.env` задай `DAILY_BUDGET_USD` и `MONTHLY_BUDGET_USD`. Это мягкие лимиты самого бота: когда
   они исчерпаны, бот вежливо сообщит, что лимит закончился.

### Сколько это стоит

`claude-opus-5-5` стоит $4 за 1M входных токенов и $20 за 1M выходных. История диалога кэшируется,
поэтому повторная отправка контекста обходится примерно в 10% цены. Обычное сообщение стоит
**$0.01–0.03**, один веб-поиск добавляет $0.01. При 30–50 сообщениях в день выходит примерно $10–30
в месяц. Сэкономить можно так:
- `CLAUDE_EFFORT=low`: ответы быстрее и дешевле;
- `CLAUDE_MODEL=claude-sonnet-5-5`: примерно вдвое дешевле;
- `CLAUDE_MODEL=claude-haiku-5-5`: в десятки раз дешевле, но слабее.

## Запуск

### 1. Подготовка

1. Создай бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируй токен.
2. Создай API-ключ в [console.anthropic.com](https://console.anthropic.com) и пополни баланс.
3. Скопируй настройки и заполни их:
   ```bash
   cd tg-assistant
   cp .env.example .env
   # впиши TELEGRAM_BOT_TOKEN и ANTHROPIC_API_KEY
   ```
4. Узнай Telegram ID. Запусти бота (шаг 2) и напиши ему `/start`: он ответит «доступ только по
   приглашению» и покажет ID. Пусть девушка сделает то же самое. Впиши оба ID в
   `ALLOWED_USER_IDS`, свой ID ещё и в `ADMIN_IDS`, затем перезапусти бота.

### 2. Локально (только чат, без мини-приложения)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app
```

Бот работает через long polling, поэтому белый IP и домен не нужны. Чат в Telegram заработает
сразу.

### 3. Мини-приложение (нужен HTTPS)

Telegram открывает мини-приложения только по `https://`. Есть два варианта.

**A. Сервер с доменом (для постоянной работы).** На VPS с Docker укажи A-запись домена на IP
сервера, затем:

```bash
# в .env:
#   DOMAIN=bot.example.com
#   WEBAPP_URL=https://bot.example.com
docker compose up -d --build
```

Caddy сам получит сертификат Let's Encrypt и будет проксировать запросы к боту. История и расходы
хранятся в томе `bot_data`.

**B. Быстрый тест через туннель:**

```bash
python -m app                                   # в одном терминале
cloudflared tunnel --url http://localhost:8080  # в другом, выдаст https://….trycloudflare.com
```

Впиши выданный адрес в `WEBAPP_URL` и перезапусти бота. Адрес туннеля меняется при каждом запуске,
поэтому для постоянной работы подходит только вариант A.

После запуска с `WEBAPP_URL` у бота появится кнопка меню с именем ассистента, а команда `/app`
откроет приложение.

## Команды бота

| Команда  | Что делает |
|----------|------------|
| `/start` | приветствие и кнопка приложения |
| `/new`   | начать новый диалог (забыть историю) |
| `/usage` | расходы за сегодня и за месяц |
| `/app`   | открыть мини-приложение |
| `/stats` | расходы по пользователям, только для `ADMIN_IDS` |

## Персонализация

- `ASSISTANT_NAME`: имя ассистента (по умолчанию «Луна»).
- `USER_NAME`: имя девушки, ассистент будет обращаться к ней по имени.
- `OWNER_NAME`: твоё имя, ассистент будет знать, кто его подарил.
- `USER_CITY`, `TIMEZONE`: город и часовой пояс для погоды, дат и времени.
- `persona.txt`: свободные инструкции, например интересы или «не ест мясо». Образец лежит в
  `persona.example.txt`.

## Устройство

```
tg-assistant/
├── app/
│   ├── __main__.py       # запуск: бот (polling) + веб-сервер в одном процессе
│   ├── config.py         # настройки из .env
│   ├── assistant.py      # Claude API: стриминг, веб-поиск, fallback, лимиты
│   ├── storage.py        # SQLite: история и расходы
│   ├── telegram_bot.py   # хендлеры aiogram, стриминг через редактирование сообщения
│   ├── tg_format.py      # Markdown → HTML Telegram, нарезка длинных ответов
│   └── webapp_server.py  # aiohttp: index.html и /api/*, проверка initData
├── webapp/
│   ├── index.html        # HTML5-интерфейс мини-приложения
│   └── vendor/           # marked + DOMPurify (локально, без внешних CDN)
├── tests/                # pytest, без сети и без расходов
├── Dockerfile, docker-compose.yml, Caddyfile
└── .env.example
```

Технические детали:
- Запросы идут через `client.beta.messages.stream` со стримингом. Включены авто-кэш промптов,
  `output_config.effort` и серверный `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`):
  если классификатор безопасности ошибочно отклонит безобидный запрос, API сам повторит его на
  подходящей модели. Отключается через `ENABLE_FALLBACKS=false`.
- В истории хранится только текст ответов, без блоков рассуждений. Поэтому старые сообщения можно
  обрезать без ошибок API. Обрезка идёт пачками (`MAX_HISTORY_MESSAGES` → `TRIM_TO_MESSAGES`),
  чтобы кэш сбрасывался редко.
- Если закрыть мини-приложение посреди ответа, ответ всё равно допишется и сохранится в истории.
